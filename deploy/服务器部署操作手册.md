# 店小C · 服务器部署操作手册（面向完全没部署过的同学）

> 目标：把项目部署到一台云服务器，得到一个 `https://你的域名` 公开网址，写进 PDF 给评委体验。
> 全程只复制命令即可，遇到报错先看文末「常见问题」。预计耗时 40–90 分钟（含域名生效等待）。

---

## 0. 架构（先理解，不复杂）

```
评委浏览器  ──HTTPS 443──▶  Nginx（你的服务器）
                               ├─ /            前端静态文件 /var/www/dianxiaoc
                               ├─ /api/*  ──▶ 127.0.0.1:3000  Node 后端(PM2)
                               └─ /ws     ──▶ 127.0.0.1:3000  WebSocket
```
- 后端**只监听本机 3000**，不对外；对外只有 Nginx 的 80/443。
- 前端构建时 `VITE_API_BASE` 为空，自动走同域 `/api`，WS 自动走 `wss://域名/ws`。
- 云安全组**只开 22、80、443，绝不开放 3000**。

## 1. 购买与准备（用团队本人实名账号）

1. 买一台学生云主机：阿里云/腾讯云学生套餐，**2 核 2G 起步即可**，系统选 **Ubuntu 22.04 LTS**。
2. 买一个域名（任意后缀都行，首年很便宜），在控制台做**实名认证**。
3. 在域名解析里加一条 **A 记录**：主机记录 `@`（或用 `demo`），记录值填服务器**公网 IP**。
4. 在云控制台「安全组/防火墙」放行入方向：**22(SSH)、80、443**。
5. 重置一次服务器 root 密码或绑定 SSH 密钥，记下公网 IP。

> 备案说明：大陆地域服务器绑定域名做 80/443 访问，多数云厂要求域名备案（需数天）。
> 若来不及备案：① 直接用 `http://公网IP` 先上（PDF 放 IP，能跑）；② 或选中国香港/海外轻量服务器免备案。

## 2. 上传代码

在**本机**项目根目录打包（排除依赖）：

```bash
# 在 03_产品Demo 目录
tar --exclude='**/node_modules' --exclude='**/.vite' --exclude='server/data' -czf dianxiaoc.tar.gz .
scp dianxiaoc.tar.gz root@你的IP:/opt/
```

在**服务器**上：

```bash
ssh root@你的IP
mkdir -p /opt/dianxiaoc && cd /opt/dianxiaoc
tar -xzf /opt/dianxiaoc.tar.gz
ls          # 应看到 server / store-app / deploy
```

（也可用 WinSCP、FileZilla 图形化上传解压。）

## 3. 配置后端环境变量

```bash
cd /opt/dianxiaoc/server
cp .env.production.example .env
nano .env
```

必填两项：
- `AUTH_SECRET`：在服务器执行 `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"` 生成，粘进去；
- `LLM_API_KEY` / `LLM_VL_API_KEY`：填通义千问 key（没有 key 也能跑，AI 会降级为规则文案并标注）。

`HOST` 保持 `127.0.0.1` 不要改。保存退出（nano：Ctrl+O 回车，Ctrl+X）。

## 4. 一键部署

```bash
cd /opt/dianxiaoc/deploy
chmod +x deploy.sh
./deploy.sh
```
脚本会自动：装 Node22/nginx/pm2 → 装依赖 → 构建前端 → 发布到 /var/www/dianxiaoc → PM2 启动后端 → 配 Nginx → 配每日 03:30 重置数据 → 本机健康检查。

## 5. 域名与 HTTPS

```bash
sudo nano /etc/nginx/sites-available/dianxiaoc   # 把两处 your-domain.com 改成你的域名
sudo nginx -t && sudo systemctl reload nginx
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d 你的域名                  # 自动签证书并把 80 跳转 443
```

## 6. 上线后验收清单（逐条做）

- [ ] 电脑浏览器打开 `https://你的域名` → 出现登录页（无任何"演示账号列表"）
- [ ] `liqiang/123456` 登录 → 今日巡店；`wangmin/123456` → 区域看板；`zhangdajie/123456` → 店主页
- [ ] 业代走一遍拍照诊断，AI 有结果（有 key 走真模型，无 key 有降级提示）
- [ ] 经理下派任务，业代页**实时**弹出待办（验证 wss）
- [ ] 手机 4G/5G 网络（不连 WiFi）打开网址同样正常
- [ ] 访问 `https://你的域名/api/v1/auth/demo-accounts` 返回 404（确认口令端点已关）
- [ ] 故意连续输错密码 11 次 → 第 11 次返回 429（确认限流生效）
- [ ] `sudo ufw status` 或云安全组确认 **3000 端口未对公网开放**

## 7. 日常运维命令

```bash
pm2 status                 # 看进程
pm2 logs dianxiaoc-server  # 看实时日志
pm2 restart dianxiaoc-server
cd /opt/dianxiaoc/server && node ../deploy/scripts/reset-data.mjs   # 手动重置一次数据
```

更新版本：本地重新打包上传解压后，再跑一次 `./deploy.sh` 即可（幂等）。

## 8. 常见问题

| 现象 | 原因/处理 |
|---|---|
| 网址打不开、502 | 后端没起：`pm2 logs` 看报错；多半是 server/.env 没配或 Node 版本 <22.5 |
| 登录提示服务不可用 | 同域反代没生效：确认 Nginx 有 `location /api/`，`curl http://127.0.0.1:3000/health` 应返回 ok |
| 经理下派业代收不到实时提醒 | `/ws` 的 Upgrade 头没配，或用了 http 打开 https 站；按本手册 nginx 模板检查 |
| 拍照诊断报 429 | AI 限流（默认每用户每分钟 12 次），等一分钟；阈值在 server/src/rateLimit.js |
| 重启后所有人掉登录 | AUTH_SECRET 没固定，按第 3 步重新生成并写进 .env，PM2 restart |
| 证书签发失败 | 域名解析没生效或 80 端口没开；先 `curl http://域名` 能通再签证书 |
